Label printer setup

For a Brother QL sitting on your desk, not on the server. Answer the three questions below, download the script, read it, run it. It sets up two small services on your computer that carry the printer to ShelfOS.

@ port

An account on the server machine, reached over ssh — not your ShelfOS login. The install created shelfos-tunnel for exactly this, and it is filled in above when the server knows its name. That account has no privileges and no shell: an authorised key may bind one port on the server and do nothing else — no commands, no other ports, no connections out.

Leave this as it is unless you know otherwise. The script creates that name, so the printer keeps it across replugs instead of moving between /dev/usb/lp0 and lp4.

The port is already the one ShelfOS expects; change it only if something on your computer uses it. The group is what lets you open the printer without root — plugdev on most desktops, lp on systems that keep printers there.

{% if can_register %}
Nothing to do on the server.

The script makes its own ssh key on this computer and registers the public half with ShelfOS, over the session you are signed in with now. The private half never travels — this page hands out a script, never a credential — and the key it registers may do exactly one thing here: carry this printer. You need no account on the server and nothing to type there.

The script can register itself for a week after you download it; after that download it again. An admin can see the machines that have registered, and withdraw one, with ./shelfos.sh tunnel-key list and remove.

{% else %}
This one needs a hand on the server.

The script makes its own ssh key on this computer — the private half never travels — but this ShelfOS cannot register it for you, either because the server was not set up for that or because a read-only account may not change what the server accepts. The first run stops and prints one line to run where ShelfOS is installed: 

./shelfos.sh tunnel-key add "ssh-ed25519 AAAA... shelfos-label@your-machine"

Then run the script here again and it carries on. ./shelfos.sh tunnel-key list shows what is authorised, and remove withdraws a machine.

{% endif %}
The script asks for sudo. Read it first.

With root it does exactly three things: writes a udev rule so the printer keeps one name, adds you to the group above, and enables lingering so the services run when you are not logged in. Everything else lands in your home directory. Undo it later with --uninstall, which leaves the group and the lingering alone because they may be older than this. 

less ~/Downloads/shelfos-label-setup.sh
bash ~/Downloads/shelfos-label-setup.sh --dry-run
bash ~/Downloads/shelfos-label-setup.sh

--dry-run prints what it would do and never calls sudo. --show-bridge prints the printer bridge it carries, so you can read that too. The file names your server and your login, so delete it when you are done.

Is it working?

Once both services are running, this asks the printer what tape it is holding — the same question printing asks, over the same path.
